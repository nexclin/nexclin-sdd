## 7. Armadilhas aprendidas, e três são novas

**Testar RLS sem banco local e sem credencial é possível.** Dentro de
`BEGIN`/`ROLLBACK`:

```sql
SET LOCAL ROLE authenticated;
SET LOCAL "request.jwt.claims" = '{"sub":"<user_id>","role":"authenticated"}';
```

A partir daí `auth.uid()` responde aquele usuário e o RLS decide de verdade. Foi
o que fechou os critérios 4 e 5 do FR-005 e os comportamentos do FR-006.

**Tabela temporária não serve para acumular resultado nesse teste.** Ela nasce do
superusuário e a parte que interessa roda como `authenticated`, então o teste
morre com `42501` **antes** de exercitar o que existe para exercitar. Use
`set_config` com prefixo próprio, que não exige permissão de ninguém.

**No editor de SQL da plataforma, clique por REFERÊNCIA e não por coordenada.**
O botão Run muda de altura conforme o painel do chat rola, e clique por
coordenada acaba navegando para fora. `Escape` fecha o painel inteiro. Metade de
uma sessão foi perdida nisso antes de virar regra.

**Verificação pode passar por vacuidade.** No vermelho do FR-005, três checagens
liam OK com a tabela não existindo: "zero policies de UPDATE" é trivialmente
verdadeiro quando não há tabela. Condicione ao objeto existir.

**Antes de comparar número, confira em qual clínica a sessão está.** Sair de uma
impersonação devolve a conta para a clínica própria dela, e os relatórios passam
a mostrar outra base. Custou um susto de regressão inexistente.

**`due_date` e `completed_at` em `tasks` são TIMESTAMPTZ.** Postgres não define
`timestamptz + integer`. Converta os dois lados com `::date`.
